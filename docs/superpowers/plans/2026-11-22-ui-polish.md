## Review Focus

1. **Pill text clipped off the notification edge.** Fitting is estimated, not measured by the system; an over-estimate drops the last (Chitas) pill. Pure fitter must prefer shrinking too much over overflowing. → Task 1.
2. **A Tanya day whose lesson crosses a chapter or part boundary.** Range refs across chapters return nested chapters; across a *part* no range can be formed at all. Must degrade to the start segment, never blank the leg. → Task 4.
3. **Extension that adds nothing.** An edge chapter that is already complete makes the "rest of chapter" fetch return no new verses; the extension must then continue to the neighbouring chapter in the same call instead of appearing dead. → Task 5.
4. **Scroll-triggered loading firing on its own.** A short expanded leg has its end sentinel on screen immediately; it must not auto-chain loads until the user actually scrolls. → Task 6.
5. **Chitas row on Shabbat/Yom Tov in the widget.** The banner has three states (before lighting / Shabbat Shalom with Havdalah / after Havdalah) plus Yom Tov without a Havdalah time. → Task 2.

### Task 5: Per-leg window and extension logic (data + ViewModel)

> User: "the chitas should be scrollable as for the other scriptures. let the trigger regions for scrolling be self-contained for each of the subsections (eg scrolling down from the chitas will display the next part, likewise for the chumash and tehilim subsections of chitas)."

**Decided semantics:** each of the three legs extends independently, **both directions**, in whole-chapter steps, matching the other readers. A leg is a verse-bounded slice of a book, so extending is verse-coverage based, not chapter-replacement based:
- Down: if the last chapter may be incomplete, fetch that whole chapter and add only the verses **after** the last covered verse as a new block; if that yields nothing, the chapter was already complete, so continue in the **same call** to the next chapter (whole) as a new block with a chapter heading.
- Up: symmetric, adding only verses **before** the first covered verse, then the previous chapter.
- Sefaria's `next`/`prev` (chapter-granular, e.g. `"Genesis 31"`) give the neighbouring chapters; they are null at the book's ends (then the leg can't extend that way).
- **Do NOT trust `next`/`prev` from a verse-bounded or trimmed fetch.** They are relative to the last/first chapter *in the requested range*, not to the verses actually shown. Verified: after Task 4 a cross-chapter Tanya lesson `4:50-5:1` is trimmed to chapter 4 only, yet the response says `next = "…Acharon 6"` — it would skip chapter 5 entirely. Rule: take `next`/`prev` only from (a) a **whole-chapter** fetch (`Psalms.44-48` → `Psalms 49`; a chapter-level fetch such as `"Genesis 30"`), or (b) the response for the edge chapter you fetch in order to complete it. For any verse-bounded or trimmed edge, treat the neighbour as *unknown until the edge chapter has been fetched*, and read it from that response. `canExtend…` is optimistic (true) while the neighbour is still unknown and becomes accurate after the first fetch.
